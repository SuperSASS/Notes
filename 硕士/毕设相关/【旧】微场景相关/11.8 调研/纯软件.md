# 基于场景的软件测试:纯软件系统测试方法综述与前沿进展(2021-2024)

## 摘要

调研了基于场景的软件测试领域,**聚焦于纯软件系统**(移动应用、Web应用、API、桌面软件)。覆盖2021-2024年顶级会议(ICSE/FSE/ASE/ISSTA)和期刊(TSE/TOSEM)的最新进展。

**核心发现**:

1. **场景测试已成为主流范式**:从传统单元测试向用户场景驱动测试的范式转变已完成,工业界广泛采用(字节跳动Fastbot2、Meta TestGen-LLM)
2. **LLM引发技术革命(2023-2024)**:大语言模型在场景理解、生成、执行中展现突破性能力,但仍存在幻觉、正确性等问题
3. **混合方法成为趋势**:LLM+程序分析+强化学习的混合方法优于单一技术,如SymPrompt(LLM+符号执行)、Fastbot2(模型+RL)
4. **工业化落地加速**:Fastbot2报告字节跳动50.8%开发者修复bug,TestGen-LLM在Meta达73%接受率,显示实际生产价值
5. **关键技术挑战仍存**:预言机问题、测试维护、场景老化、脆弱测试等问题需要持续研究

## 第一部分:基于场景的软件测试领域综述

### 1.1 背景故事与核心问题

#### 软件测试范式演进(1948-2024)

软件测试经历六个阶段:调试导向期(1948-1956)→演示导向期(1957-1978)→破坏导向期(1979-1982)→评估导向期(1983-1987)→预防导向期(1988-1995)→场景导向期(2000-至今)。

**关键里程碑**:

- **2003**:Cem Kaner提出"场景测试"概念
- **2003-2004**:Hans Buwalda引入"肥皂剧测试"
- **2019-2024**:LLM驱动的场景测试兴起

#### 传统测试方法的五大困境

1. **集成盲区**:单元测试忽略端到端工作流缺陷
   - Healthcare.gov(2013):组件测试通过但端到端注册流程失败,20亿美元损失
   - Knight Capital(2012):45分钟损失4.4亿美元

2. **需求脱节**:详细测试用例难以反映真实用户使用方式

3. **维护负担**:软件维护消耗67%+开发成本,21%缺陷来自最后一刻修复

4. **沟通鸿沟**:技术测试用例难以与业务利益相关者共鸣

5. **真实场景缺失**:实验室环境测试无法模拟野外行为

#### 重大软件失败案例

**Therac-25放射治疗机(1985-1987)**:
- 根因:竞态条件,操作员快速输入序列触发
- 场景缺失:真实操作模式未测试
- 后果:多人死亡

**Ariane 5火箭(1996)**:
- 根因:复用代码未在新速度场景测试,64位转16位溢出
- 后果:5亿美元损失

**Boeing 737 MAX(2018-2019)**:
- 根因:传感器故障+飞行员响应场景测试不足
- 后果:346人死亡,全球停飞

**共同模式**:复用未验证、集成场景缺口、罕见边缘场景、高负载场景、人机交互场景遗漏

**经济影响**:2002年研究显示,软件缺陷年损失595亿美元,改进测试可减少225亿美元(1/3)。

### 1.2 场景的定义与建模方法

#### 多维定义

1. **场景测试(Kaner,2003)**:基于假设性故事的测试,具有可信、激励性、复杂、易评估特征
2. **测试场景(IEEE)**:描述最终用户使用软件的故事
3. **用例场景(Jacobson,1992)**:参与者与系统交互的事件序列
4. **UML交互场景**:对象间消息交换的特定实例

#### 场景核心要素

1. **前置条件**:系统初始状态、数据设置、认证
2. **触发器**:启动场景的事件
3. **参与者**:主要/次要角色
4. **动作序列**:步骤式工作流
5. **预期结果**:可观察结果、最终状态
6. **替代流**:异常处理、错误情况

#### 场景vs测试用例

| 维度 | 测试用例 | 测试场景 |
|------|---------|---------|
| 粒度 | 单步骤 | 多步骤工作流 |
| 描述 | 详细技术规格 | 高层次业务描述 |
| 示例 | "验证登录" | "登录→搜索→购买" |
| 可读性 | 技术性强 | 业务人员可理解 |

#### 1.3.2 场景生成技术

**组合测试(t-wise覆盖)**:
- **原理**:大多数故障由1-2参数交互引起
- **算法**:IPOG(ACTS工具,4000+用户)、FastCA(ICSE 2021)、SamplingCA(FSE 2022)
- **效果**:2-wise捕获70-90%故障,显著减少测试用例

**搜索算法**:
- **遗传算法**:GTSG,记忆算子减少40%资源消耗
- **强化学习**:Fastbot2(N步SARSA),抖音覆盖率+27%
- **模拟退火**:FastCA优化约束覆盖阵列

**LLM驱动生成(2023-2024突破)**:

| 工具 | 会议 | 创新点 | 效果 |
|------|------|--------|------|
| TestGen-LLM | Meta 2024 | 验证过滤器+迭代生成 | 73%工程师接受率 |
| ChatUniTest | FSE 2024 | 自适应上下文+生成-验证-修复 | 错误纠正增强 |
| SymPrompt | FSE 2024 | 多阶段提示+符号执行 | 正确测试+5倍 |

**局限**:幻觉(生成不存在方法)、编译率低(20-80%)、类型系统困难、成本高

#### 1.3.3 场景选择与优先级

**覆盖率驱动**:

**多样性驱动**:
- **行为多样性**(b-div)优于工件多样性(a-div)

**多目标优化**(NSGA-II):
- 平衡覆盖率+成本+多样性

#### 1.3.4 场景执行与预言机

**自动化框架**:
- **Web**:Selenium WebDriver,Cypress,Playwright
- **移动**:Appium,Fastbot2(开源,1100+ stars)
- **API**:EvoMaster(发现80个真实bug),RESTler(GitLab 28个bug)

**预言机问题**(最难挑战):

**定义**:**确定测试预期结果**的困难,或实际输出是否与预期一致。

**解决方案**:

1. **变形测试**(Chen 1998,750+论文):
   - 原理:多个相关输入输出间的关系
   - 示例:"罗马酒店"N个结果,按价格筛选应≤N
   - 采用:Google(GraphicsFuzz),GCC,LLVM
   - 有效性:小集多样MR≈完整预言机(TSE 2014)

2. **神经预言机**(TOGA,ICSE 2022):
   - Transformer生成断言和异常预言机
   - 96%准确率,发现57个真实bug
   - 局限:24%误分类,47%假阳性(FSE 2023评估)

3. **LLM预言机**(TOGLL 2024):
   - 比传统ML提高10倍
   - 检测1,023个EvoSuite无法发现的bug
   - 仍需人工监督

4. **不变式预言机**:
   - Daikon动态不变式检测
   - AGORA/AGORA+(ISSTA 2023):106种不变式,REST API

#### 1.3.5 场景演化与维护

**维护类型**(IEEE 1219):
- 纠正性21%,适应性25%,完善性50%+,预防性4%

**演化挑战**:
- 软件火山:750 gigalines COBOL + 900 gigalines C,35 gigabugs
- 维护消耗67%+成本
- Lehman复杂性增长定律

**场景老化检测**:
- 持续失败(业务规则变化)
- UI定位器频繁中断
- 场景不匹配当前工作流
- 执行时间显著增加

**维护策略**:
1. **持续重构**:保持测试代码清洁
2. **可追溯性矩阵**(RTM):需求→用例→测试用例
3. **分类**:可重用vs过时
4. **AI自愈**(mabl,Testim):动态定位器更新,减少95%维护
5. **文档实践**:记录业务逻辑和理由

**回归选择**:
1. 全部重测(最全面但低效)
2. RTS(选择受影响子集)
3. 优先级排序(高/中/低)
4. 混合方法

## 第二部分:代表性论文深度解读

### 论文1: QTypist(ICSE 2023)

**引用**: Zhe Liu et al. "Fill in the Blank: Context-Aware Automated Text Input **Generation for Mobile GUI Testing**." ICSE 2023, pp. 1355-1367.

**问题**:移动GUI测试需语义适当文本输入以探索场景,传统方法(随机/字典)导致40-60%页面无法访问,覆盖率严重受限。

**方法**:填空任务表述+T5-base微调
- **上下文提取**:部件属性(resource-id,hint)+兄弟部件+页面上下文+应用类别
- **提示构造**:"Fill in the blank for [EditText] on Travel app...Hint:'Enter destination'...Generate: ___"
- **LLM生成**:T5-base(220M)领域微调,15,847样本自动提取,训练4小时

**结果**:
- 通过率**87.2%** vs Hint2Input 45.3%(+93%),GPT-3.5 38.4%(+127%)
- 集成DroidBot:活动覆盖+42%,页面覆盖+52%,bug检测+122%
- 跨15类别稳定(标准差5.8%)
- 推理\<100ms

**开源**:完整代码+15,847数据集+模型权重(Hugging Face)

**贡献**:首个填空任务表述;自动数据管道;实际影响显著;即插即用集成;领域微调有效性

**局限**:仅英语;复杂约束困难;领域特异性;GPU需求;动态验证无法处理

**场景关联**:解锁先前无法访问场景(电商搜索→购买,旅行预订,社交发布,表单提交),扩展可测试场景空间

### 论文2: Fastbot2(ASE 2022)

**引用**: Zhengwei Lv et al. "Fastbot2: Reusable Automated **Model-based GUI Testing** for Android Enhanced by Reinforcement Learning." ASE 2022, Article 135.

**问题**:工业应用频繁更新(每周),传统工具每次从零测试,忽略历史知识,无法满足CI/CD快速反馈需求。

**方法**:概率模型+强化学习+可重用知识
- **概率模型M=(E,A,δ)**:超事件抽象,P(e,Aᵢ)=N(e,Aᵢ)/N(e)
- **混合选择**:
  - 模型扩展(新事件随机)vs模型利用(选择最可能到达未覆盖Activity)
  - N步SARSA:Q值学习,奖励=E(eₜ)/√(N(eₜ)+1)+V/√(N(Aₜ)+1)
- **两阶段**:设置(APK反编译+历史加载)+引导探索(迭代选择-执行-更新)

**实验**:
- 抖音19.7-20.6(10版本),今日头条8.7.0-8.7.9
- 设备:10台/版本,测试时间1小时

**结果**:
- 单版本覆盖:抖音+15-25%,今日头条+10-18%
- 累积覆盖:抖音237 vs Ape 186(+27%),今日头条189 vs 173(+9%)
- 崩溃:抖音68 vs 34(+100%),今日头条38 vs 40(相当)
- 消融:RL+PM \u003e RL Only \u003e PM Only

**工业部署**:
- 字节跳动CI流水线2年
- **50.8%开发者修复bug**由Fastbot2报告
- 覆盖**80%热点Activity**
- 开源,1100+ stars

**贡献**:首个可重用方法;混合模型+RL;超事件抽象;工业验证;开源影响

**局限**:动态内容不稳定;首次运行无优势;模型维护;大应用内存需求

**场景关联**:
- 场景编码(概率模型捕获事件-活动转换)
- 场景选择(模型优先未覆盖功能)
- 多步场景(RL学习序列)
- 场景重用(版本N→版本N+1)
- 应用:回归、功能探索、深层状态、覆盖导向

### 论文3: LLM4Fin(ISSTA 2024)

**引用**: Zhiyi Xue et al. "LLM4Fin: Fully Automating **LLM-Powered Test Case Generation** for FinTech Software Acceptance Testing." ISSTA 2024, pp. 1643-1655.

**问题**:金融软件必须符合严格监管规则(自然语言),传统验收测试需:理解领域术语、提取可测试场景、创建全面测试、集成金融专业知识。人工测试20+分钟/规则,昂贵易错。

**方法**:混合LLM-算法框架,三阶段
1. **信息抽取**(微调BERT-large):
   - NER:订单类型、证券、操作、约束(F1 94.3%)
   - 关系抽取:is-a,has-a,requires,excludes(准确率91.7%)
   - 规则分类:强制、可选、条件、排他(准确率89.2%)
   - 15,000标注句,500MB语料,4×V100,12小时

2. **领域知识集成**:
   - 术语层次:ORDER_TYPE→MARKET_ORDER,LIMIT_ORDER
   - 组件关系:"价格限制订单"={账号,证券,方向,数量,价格}
   - 事件依赖:已提交→已验证→已匹配→已结算→已完成

3. **算法场景生成**:
   - 组合扩展:基础场景+可选参数组合+边界值+异常
   - 基于路径:状态转换图,覆盖有效路径+边界+无效+异常
   - 优先级:关键(强制合规)\u003e常见\u003e边缘

**实验**:
- 5个真实股票交易系统(中国主要金融机构)
- 代码15K-85K行,文档500-2000页,规则150-800/系统

**结果**:
- **业务场景覆盖98.18%**(人工87.3%,GPT-4 few-shot 72.1%),提升20%-110%
- **代码覆盖**:语句93.72%(人工89.1%),MC/DC 90.86%(人工85.2%,**首个超90%**)
- **时间**:7秒/规则(人工20-35分钟),**速度171×-300×**
- 消融:完整98.18%,无微调76.4%(-22%),无知识81.2%(-17%),无算法85.3%(-13%)
- Wilcoxon p\<0.001,5次运行\<2%方差

**开源**:Figshare+HuggingFace(13luoyu/LLM4Fin)+15,000数据集+JSON知识库+GitHub+评估脚本+50页手册

**贡献**:首个端到端自动化金融框架;混合LLM-算法;领域知识集成新方法;工业验证;超90% MC/DC;170×-300×加速

**局限**:领域特异性(方法论可迁移);自然语言歧义(\<5%);动态规则需重训;测试预言机依赖规范;多语言需新数据

**场景关联**:
- 场景提取(从NL规则识别可测试业务场景)
- 场景生成(算法生成覆盖监管要求的全面集合)
- 场景优先级(按关键性和合规重要性排序)
- 场景执行(翻译为可执行测试用例)
- 应用:监管合规、验收测试、业务流程、需求追溯

## 结论与未来方向

### 主要成就(2021-2024)

1. **LLM引发革命**:从TestGen-LLM(73%接受)到QTypist(87%通过率),展现突破性能力
2. **工业化成熟**:Fastbot2(50.8% bug)、Meta TestGen-LLM验证生产价值
3. **混合方法优势**:SymPrompt(LLM+符号执行)、Fastbot2(模型+RL)优于单一技术
4. **全面技术栈**:覆盖移动/Web/API、MBT、组合测试、LLM、知识图谱、预言机
5. **开源生态**:Fastbot2、Genie、Themis、EvoMaster、RESTler等重要工具开源

### 仍存挑战

1. **预言机问题**:TOGA 47%假阳性,变形测试无法验证绝对正确性
2. **LLM局限**:幻觉、编译率低、成本高、可解释性差
3. **维护负担**:67%+成本,场景老化,测试衰减
4. **脆弱测试**:20-24%开发者月/周遇到,侵蚀信任
5. **可扩展性**:状态爆炸,高强度CIT(4-6wise)受限

### 未来研究方向

1. **智能体测试(2025+)**:Gartner预测2028年33%应用有智能体AI,自主规划-行动-学习
2. **神经-符号深度融合**:超越简单组合,实现协同推理
3. **知识图谱+LLM**:显式测试知识表示+神经推理
4. **自适应演化测试**:持续学习、自愈、场景自动更新
5. **形式化验证集成**:LLM生成+形式化验证保证正确性
6. **跨领域迁移**:软件测试技术→军用装备、CPS、安全关键系统
